# Vibe Tool v2 — Context Intelligence Design Document

**Date:** 2026-04-27
**Goal:** Eliminate 60%+ of token waste on codebase discovery by giving Claude pre-built context. Five features that turn every session into a productive one from the first message.

**Core problem:** LLMs spend more tokens searching and understanding code than writing it. A typical session uses 60%+ of tokens on exploratory file reads, greps, and globs before writing a single line.

**Solution:** Pre-built, auto-maintained context files in a `.vibe/` project directory that Claude reads at session start instead of discovering from scratch.

---

## Architecture Overview

All v2 features share a single pattern: generate context files in `.vibe/`, instruct Claude to read them.

```
my-project/
├── CLAUDE.md                     (human-editable project context)
├── .vibe/
│   ├── codebase.md              (Feature 1: codebase knowledge base)
│   ├── handoff.md               (Feature 2: session continuity notes)
│   ├── session-context.md       (Feature 3: temporal context, NOT committed)
│   ├── errors.md                (Feature 4: error memory)
│   └── prompts/                 (Feature 5: prompt templates)
│       ├── add-endpoint.md
│       ├── add-page.md
│       ├── fix-bug.md
│       ├── add-feature.md
│       └── refactor.md
```

**Integration with v1:**
- Global CLAUDE.md (from `vibe setup`) gets a new rule: "At the start of every session, read the `.vibe/` directory if it exists. Start with `codebase.md`, then `handoff.md`, then `errors.md`."
- `vibe init` creates the `.vibe/` directory and runs initial index generation
- `vibe sync` includes `.vibe/` in its commit/push/pull (except `session-context.md`)
- Existing hooks are extended with handoff generation and pre-loader

**Key design principle:** `.vibe/codebase.md` is a navigation aid, not a source of truth. Claude uses it to find the right files fast, then reads those files before making changes. If the index conflicts with actual code, trust the code.

## Feature 1: `vibe index` — Codebase Knowledge Base

**File:** `.vibe/codebase.md`
**When written:** Post-commit hook (pattern-based) + manual `vibe index` + `vibe index --deep` (Claude-powered)
**When read:** Session start
**Committed to Git:** Yes

### Output format

```markdown
# Codebase Index (auto-generated by vibe index)
Last updated: 2026-04-27 14:30

## File Map
src/api/routes/auth.ts — Authentication routes (login, signup, logout)
src/api/routes/products.ts — CRUD for product listings
src/db/schema.ts — Database schema: users, products, orders
src/components/ProductCard.tsx — Product card component

## Exports
### src/api/routes/auth.ts
  POST /api/auth/login — loginHandler(email, password)
  POST /api/auth/signup — signupHandler(email, password, name)

### src/db/schema.ts
  table users: id, email, passwordHash, createdAt
  table products: id, title, price, sellerId, images, createdAt

### src/lib/jwt.ts
  function signToken(userId: string) → string
  function verifyToken(token: string) → { userId: string }

## Dependencies
auth.ts → db/schema.ts, lib/jwt.ts
products.ts → db/schema.ts, lib/storage.ts

## Patterns
- API routes use zod validation via middleware/validate.ts
- Auth via JWT in Authorization header
- All DB queries use drizzle ORM
```

### Parsing approach

**Pattern-based (default, fast, free):**

JS/TS files:
- `export function/const/class` → extract name and signature
- `app.get/post/put/delete` or `router.*` → extract API routes
- `import ... from` → extract dependencies

Python files:
- `def ` at module level → extract function name and args
- `class ` → extract class name
- `@app.route` / `@router.get` etc → extract API routes
- `from/import` → extract dependencies

Special files:
- `schema.ts/py`, `models.ts/py` → extract table/model definitions
- `package.json` / `pyproject.toml` → extract scripts and dependencies

**Claude-powered (`--deep` flag):**
- Runs a Claude Code session that reads the codebase and writes a richer index
- Generates semantic file descriptions (purpose, not just exports)
- Identifies patterns and conventions
- Costs tokens but produces higher quality index

### Commands

```bash
vibe index              # Pattern-based scan (<2s, free)
vibe index --deep       # Claude-powered analysis (richer, costs tokens)
```

### Failure modes and mitigations

| Failure | Mitigation |
|---|---|
| Regex misses dynamic exports | `--deep` mode catches these; parser improves over time |
| Stale index after uncommitted changes | Index shows timestamp; global rule: "if >1hr old, verify against source" |
| Business logic not captured | Index is for navigation. Claude still reads source before modifying |
| Wrong file description | `--deep` mode generates semantic descriptions |

## Feature 2: Session Handoff — Auto-Generated Continuity Notes

**File:** `.vibe/handoff.md`
**When written:** Post-session hook (deterministic script, not Claude)
**When read:** Next session start
**Committed to Git:** Yes

### Output format

```markdown
# Session Handoff
Last session: 2026-04-27 14:30 (45 min)

## What was done
- Added Stripe payment integration
- Created /api/orders/checkout route with zod validation
- Wrote 6 tests for checkout flow (all passing)

## In progress
- Webhook handler for payment confirmation (file created, not implemented)

## Blocked on
- Need STRIPE_WEBHOOK_SECRET in .env for webhook verification

## Next up
- Implement webhook handler in src/api/routes/webhook.ts
- Add order status update logic
- Add E2E test for full payment flow

## Files changed
- Modified: src/db/schema.ts (added orders table)
- Created: src/api/routes/checkout.ts
- Created: src/api/routes/webhook.ts (skeleton only)
- Created: tests/api/checkout.test.ts
```

### How it generates

Post-session hook script:
1. `git diff` and `git log` comparing HEAD at session start vs session end
2. Reads previous handoff to check what was "Next up" — flags completed items
3. Parses cached test results for pass/fail counts
4. Uncommitted changes → "In progress" section
5. Writes `.vibe/handoff.md`

Deterministic — no Claude, no tokens, runs in <1s.

### Session start tracking

The pre-session hook records the current HEAD SHA to a temp file (`.vibe/.session-start-sha`). The post-session hook compares against this to know what changed during the session.

## Feature 3: Session Pre-loader — Temporal Context

**File:** `.vibe/session-context.md`
**When written:** Pre-session hook (shell script)
**When read:** Session start
**Committed to Git:** No (added to `.gitignore`)

### Output format

```markdown
# Session Context (auto-generated, do not edit)
Generated: 2026-04-27 15:00

## Git State
Branch: feature/payments (5 commits ahead of main)
Uncommitted changes:
  - src/api/routes/webhook.ts (modified, 12 lines)

## Recent Commits (last 5)
- feat: add checkout API route (2h ago)
- feat: add orders table to schema (2h ago)
- test: add checkout flow tests (2h ago)
- feat: add Stripe dependency and config (3h ago)
- refactor: extract validation middleware (yesterday)

## Test Health
Last run: 28 passed, 0 failed
Failing tests: none

## Environment Notes
- .env has: DATABASE_URL, STRIPE_SECRET_KEY
- .env missing: STRIPE_WEBHOOK_SECRET (referenced in code but not set)
```

### How it generates

Pre-session hook shell script:
1. `git status` → branch, uncommitted changes
2. `git log --oneline -5` → recent commits with relative timestamps
3. Reads cached test results from project index
4. Scans `.env.example` vs `.env` → flags missing variables (if `.env.example` exists)

Pure shell/Python. No Claude, no tokens. <1 second.

### Why not committed

This is machine-specific temporal state. The other Mac has a different branch checked out, different uncommitted changes. Committing it would overwrite the other machine's reality.

## Feature 4: Error Memory — Never Debug the Same Thing Twice

**File:** `.vibe/errors.md`
**When written:** By Claude during debugging (primary) + `vibe error add` (manual)
**When read:** Session start + during debugging
**Committed to Git:** Yes

### Output format

```markdown
# Error Memory
Errors encountered and their solutions. Read this before debugging.

## ERR-001: Module not found @/lib/auth
**When:** Import paths with @ alias
**Cause:** tsconfig.json baseUrl and paths not configured
**Fix:** Add `"baseUrl": "."` and `"paths": {"@/*": ["src/*"]}` to tsconfig.json
**Date:** 2026-04-27

## ERR-002: Stripe webhook returns 400
**When:** Receiving Stripe webhook POST requests
**Cause:** Body must be raw buffer for signature verification, not parsed JSON
**Fix:** Use `express.raw({type: 'application/json'})` on the webhook route
**Date:** 2026-04-28
```

### How entries get added

**1. Claude writes them (primary).** Global CLAUDE.md rule:

> "When you encounter an error that required non-obvious debugging (not a simple typo), append it to `.vibe/errors.md` using the ERR-NNN format. Include: when it happens, root cause, and the fix."

**2. `vibe error add` command (manual):**

```bash
vibe error add
# Prompts: title, when, cause, fix
# Appends to .vibe/errors.md with next ERR-NNN number
```

**3. `vibe error list` command:**

```bash
vibe error list
# Prints all errors in a table
```

### How Claude uses it

Global CLAUDE.md rule: "When debugging, check `.vibe/errors.md` first — this may be a known issue with a documented fix."

## Feature 5: Prompt Templates — Consistent Quality With Zero Effort

**File:** `.vibe/prompts/*.md`
**When written:** `vibe init` (defaults) + `vibe prompt create` (custom)
**When read:** When user starts a task
**Committed to Git:** Yes

### Default templates

**add-endpoint.md:**
```markdown
Add a new API endpoint: [describe what it does]

Context for Claude:
- Check .vibe/codebase.md for existing routes and patterns
- Follow the route pattern in src/api/routes/
- Use the validation middleware (see codebase index for location)
- Add tests in the tests/api/ directory matching existing test patterns
- Update .vibe/codebase.md Exports section when done
```

**add-page.md:**
```markdown
Add a new page: [describe what the page does]

Context for Claude:
- Check .vibe/codebase.md for existing components and pages
- Follow the existing page structure and layout patterns
- Reuse existing components before creating new ones
- Add E2E test with Playwright for the new page
- Update .vibe/codebase.md File Map when done
```

**fix-bug.md:**
```markdown
Fix this bug: [describe what's broken]

Context for Claude:
- Read .vibe/errors.md first — this may be a known issue
- Write a failing test that reproduces the bug BEFORE fixing it
- Run existing tests to make sure the fix doesn't break anything else
- If this was non-obvious, add it to .vibe/errors.md
- Update .vibe/handoff.md with what was fixed
```

**add-feature.md:**
```markdown
Add this feature: [describe what it does]

Context for Claude:
- Read .vibe/codebase.md to understand existing architecture
- Follow existing patterns for similar functionality
- Write tests first (TDD)
- Update .vibe/codebase.md when done
```

**refactor.md:**
```markdown
Refactor: [describe what to restructure]

Context for Claude:
- Run all tests FIRST to establish a green baseline
- Make structural changes WITHOUT changing behavior
- Run tests after each change to verify nothing broke
- Update .vibe/codebase.md if file locations or exports changed
```

### Commands

```bash
vibe prompt list                  # List available templates
vibe prompt show add-endpoint     # Print template to terminal
vibe prompt copy add-endpoint     # Copy to clipboard
vibe prompt create my-template    # Create custom template
```

## Changes to Existing v1 Components

### Global CLAUDE.md additions

Added by `vibe setup` (appended to existing quality rules):

```
## Context Loading Rules (added by vibe-tool)

11. At the start of every session, read the `.vibe/` directory if it exists.
    Read in order: codebase.md, handoff.md, errors.md, session-context.md.
12. The codebase index (.vibe/codebase.md) is a navigation aid, not a source of truth.
    Use it to find files fast, then read the actual source before making changes.
    If the index conflicts with actual code, trust the code and re-run `vibe index`.
13. When you encounter a non-obvious error, append it to .vibe/errors.md
    using the ERR-NNN format with: when, cause, and fix.
14. After each session milestone, ensure .vibe/codebase.md still reflects
    any new or changed files, exports, or patterns.
```

### Hook extensions

| Hook | v1 Action | v2 Addition |
|---|---|---|
| Pre-session | `vibe sync pull` | + Generate `session-context.md` + Record session start SHA |
| Post-commit | Run tests, update index | + Run `vibe index` (pattern-based) |
| Post-session | Commit context, `vibe sync push` | + Generate `handoff.md` + Include `.vibe/` in commit |

### `vibe init` extensions

After existing scaffolding, also:
1. Create `.vibe/` directory
2. Run `vibe index` to generate initial `codebase.md`
3. Create empty `errors.md` with header
4. Copy default prompt templates to `.vibe/prompts/`
5. Add `session-context.md` to `.gitignore`

### CLI command additions

| Command | What it does |
|---|---|
| `vibe index` | Generate codebase knowledge base (pattern-based) |
| `vibe index --deep` | Generate codebase knowledge base (Claude-powered) |
| `vibe error add` | Manually add an error to error memory |
| `vibe error list` | List all recorded errors |
| `vibe prompt list` | List available prompt templates |
| `vibe prompt show <name>` | Print a template |
| `vibe prompt copy <name>` | Copy a template to clipboard |
| `vibe prompt create <name>` | Create a custom template |

## Known Limitations

1. **Pattern-based parsing is imperfect.** Regex cannot handle all code patterns (dynamic exports, metaprogramming, computed routes). `--deep` mode compensates but costs tokens.
2. **Handoff quality depends on commit messages.** Sessions with zero commits produce thin handoffs. Mitigated by global CLAUDE.md enforcing frequent, descriptive commits.
3. **Error memory is append-only.** Over time it may accumulate stale entries. Manual cleanup needed periodically. Could add `vibe error remove <id>` later.
4. **Prompt templates are static starting points.** They don't auto-adapt to the specific project's patterns — they provide consistent instructions that reference the codebase index which does adapt.
5. **Pre-loader env checking requires .env.example.** If the project doesn't use .env.example, the environment notes section will be empty.
